# 市场发现与报告规范

适用于选股、新增候选和收盘总结。`codex_cycle.py` 分析 plan.watchlist，并从完整涨停池中加入少量研究观察股；排板/回封证据接入普通 run。它尚不覆盖全部未涨停机会或完整滚动淘汰，本规范要求 Codex 同轮补充研究。

## 每轮滚动观察池（必做）

每个有效交易时段轮次均执行本节，不以是否允许买入、cycle 是否有待发报告或是否先发现板块变化为前提。收盘首轮汇总；非交易时段不自动刷新。`codex_cycle.py run` 已处理交易计划和有限涨停研究短名单，本节的跨轮优先级管理与未涨停候选仍由 Codex 同轮补充，不得把普通 run 成功视作全市场滚动选股完成。

1. 读取最新交易计划、上一轮研究归档和最近交易日的观察池。计划名单、已登记持仓用于纪律/风险监控；滚动研究池独立维护，未经授权不把候选写入 plan.json，不删除持仓监控。
2. 每轮获取当日完整涨停池、炸板池、情绪和最新板块分布，比较昨日完整数据、当日首个有效基线和上一轮。候选来源还包括上一轮未涨停的候选、炸板后的承接标的、强势板块中可核验的未涨停标的；不能只按成交额选前三，不能因退出涨停池就丢失跟踪。没有全市场未涨停扫描接口时明确覆盖范围，不宣称扫描全部股票。
3. 对合并去重的候选获取当日最新报价、动态VWAP、开盘/高低点、当日连板、历史涨幅与公告催化。先按板块扩散、持续性和实际承接筛选少量重点；高位/一字/涨停股可作参照，不因强势直接晋升买入候选。标注每个字段的时间和缺口，过期数据不得冒充本轮。
4. 逐股记录新增、保留、降权、移出优先观察或板块参照，并写证据、重新纳入条件及失效条件。数据缺失标记待核验并禁止晋升，不等同走弱；移出仅影响研究优先级，历史记录保留。跨日候选必须重新核验，不把昨日标签和价格沿用为今日信号。
5. 将本轮筛选及前轮重点候选合并为内存 research_plan，连同市场背景和硬风控交给 Jev 完整复核；研究候选不授予交易权限；正式候选仍需明确的仓位、个股启用和完整规则，不能给新发现股票偷偷沿用其他股票的仓位参数。Jev 失败则保留行情层变化并标明“模型未完成”，不能用占位“无明确主线”冒充模型结论。市场退潮时仍做研究，但买入闸门保持有效。
6. 每轮以独立编号保存不可覆盖的 `DATA_DIR/reviews/YYYY-MM-DD-HHMMSS-rolling.json` 和对应 `.md`（目录700、文件600）。JSON 至少包含 report_id、as_of、数据覆盖/缺口、市场与当日基线、候选 code/name/status、上轮状态、价格/VWAP与时间、变化原因、入场前置与失效条件、Jev状态/结果。首轮从最近候选归档初始化；已有归档损坏时保留并报错，不默默清空观察池。
7. 将本轮与最近已推送研究报告比较。新增/移出、优先级变化、确认条件触发/失效、风险变化或收盘首轮才推送；单纯价格小变动不重复发送。无变化也必须保存本轮检查记录。摘要先说名单变化，再给旧计划风险；发送结果另存同编号 delivery.json，不写入 cycle 的 claim/ack。未确认送达的补充报告下轮先按原渠道回查，不能因新一轮开始而盲重发。

## 证据与筛选

1. 用 `live_analysis._pool("ZT", YYYYMMDD)` 获取经 tc/条数校验的当日完整涨停池；配合 ZB/DT、前一交易日池及腾讯行情。勿只读 snapshot.leaders，它只是截取。行情源不可用时明确缺口，不把空结果当零家。
2. 比较同口径板块今天/昨日家数、连板梯队、首封/末封时间、开板次数、成交额和换手。开盘早段情绪依既有昨日完整数据规则；收盘用当日完整数据。行业聚类不证明共同催化；没有新闻/公告证据不要宣称题材主线已确认。
3. 从扩散方向筛出少量非一字首板/换手候选，并列出高位核心作为强弱参照。不要把所有涨停股都当候选；首板不等于低位，封单额/成交额不等于主力净买入，开板次数少不保证明日强势。尽可能补查历史涨幅、实际催化和公告，缺失则仅研究观察。
4. 校验原名单当日 lbc 与策略说明。若从二板变成六板，应明确高位接力风险和标签过时，不能原样套用二板入场规则。只输出计划修订建议，不自行改 buy_enabled、仓位、止损或买卖登记。
5. 将候选行情、完整池、前日对比、公告及现有硬风控送给 `live_jev.analyze(snapshot, research_plan, decision)`。research_plan 是内存研究副本，不覆盖 DATA_DIR/plan.json；候选保持观察/暂停买入。模型给出的观察排序不是授权开仓。若研究范围改变后主线选择不同，要说明不确定性，不能挑选最乐观答案。

## 陈小群战法在本策略中的应用

这是用户采用的规则化研究框架，不把程序规则或未经核验的观点冒充陈小群本人的原话，也不声称复刻其全部交易。

- 先验证主线持续性、情绪阶段和龙头辨识度，再研究买点；禁止仅按涨幅/成交额选股，禁止因龙头买不到而自动购买跟风股。
- 用户已授权将“一律不追涨停”改为有条件的排板/回封买入候选提醒。持续一字板先进入核心研究，不自动排除：主线和核心地位、连续有效行情及封板证据、Jev复核（回暖/发酵/分歧阶段，高潮/退潮不晋升）、市场/个股/仓位闸门均满足时，可以提醒人工核对排板机会。排队不保证成交，成交时封单可能正在减弱；五分钟快照不含个人排队位置，不能宣称可买到、可及时撤单或封板全过程稳定。当前程序以紧邻成功轮次（同日、最多间隔10分钟）的涨停池和实时买一证据作辅助；报价需各自在3分钟有效期内、两轮时间真实递进，最多允许5秒采集/时钟差；排板需两轮未记录开板，回封需两轮间开板次数或最后封板时间更新。缺前轮或首次开板后刚进入池时先观察，可能错过快速机会。这是采样能力限制，不是陈小群战法的固有阈值。
- 研究核心股首次有效分歧后的承接：板块地位未丧失、放量分歧后价格承接、动态VWAP及关键支撑、回封质量和板块联动。一次开板不等于健康分歧，一次高于VWAP不等于站稳；需连续快照与公告支持。回封可触发有条件的人工候选提醒，但必须通过同样的闸门；盘口即时强度与撤单风险仍需人工确认。
- 低位首板方向先验证新主线、资金参与和历史位置，首板本身不证明低位。整体退潮或核心断板负反馈下，研究仍继续，新买入暂停。
- 输出区分“龙头强但不可参与”“分歧待确认”“规则满足的人工候选”。当前授权仅涵盖排板/回封候选提醒，尚未授权委托、自动撤单或成交登记；不得将候选提醒描述为已下单。

## 输出

- 开头给日期、数据获取时间、市场环境与是否允许新开仓。
- 市场证据：指数与日内走势、涨停/炸板/跌停/高度、板块昨日→今日变化。
- 新候选：代码、名称、当日板数与本轮价格（收盘总结用收盘价）、入选证据、入场前置条件、失效条件、待核验信息。买点价格需基于次日实际开盘和 VWAP，不把今日收盘价当明日买入价。
- 原名单：保留、降权、仅作情绪参照及原因。没有持仓登记只代表未知实际账户持仓。
- 明日顺序：先验证退潮恢复（涨停回升、炸板回落、主线连续两日各>=4家），再看非涨停的分歧承接与既定弱转强确认，最后核对仓位和可成交性。一字/一致加速必须通过核心与封板证据复核，不无条件追买；单点高于 VWAP 不等于站稳。
- 纪律：陈小群主线与分歧，小鳄鱼仓位与确定性；首测试错0.5成、单票<=2成，总仓按计划；止损结合实际成本、T+1和流动性。末尾附“技术研究辅助，不构成投资建议。”

## 归档与通知

研究原始数据和独立报告保存到 DATA_DIR/reviews/YYYY-MM-DD-candidates.json 和 YYYY-MM-DD-market-review.md，文件权限600，不覆盖既有原始报告。
用户授权发送总结时，使用独立 Slack Bot 与飞书通道，正文标记唯一报告编号。手工补充报告分别记录发送结果：`push.send_feishu_once(text)` 返回 `(ok, receipt)` 或 `None`；`slack_bot.send_once(text)` 返回含 `ok/channel/ts/error` 的字典，不混用返回结构。调用前持久化目标与 sending 状态，返回后立即保存原渠道回执；结果不明先在原渠道回查，不盲重发；不能用一个渠道回执证明另一个已送达。自动化原 cycle 报告仍使用既有 claim/ack 流程，补充报告不能误写其送达状态。
每个有效轮次执行上述滚动研究；名单、板块、梯队或风险有重要变化时发送补充报告，收盘首轮给出综合总结。无变化不重复发送，非交易时段不自动启动新研究；用户明确要求盘后总结不受此限制。

## 三栏推送：分析、买入建议、回测验证

每份常规与补充报告明确分为三个部分：
- **市场分析**：情绪、主线、滚动观察、风险与数据时间；观察股不代表建议购买。
- **买入建议**：只列全部硬闸门和 Jev 通过、已配置仓位且可买整手的候选；列标的、参与方式、触发依据、价位条件、计划仓位上限、有效期与失效条件。没有合格标的明确写“本轮不建议新买入”，不为凑数推荐。暂停或观察股不展示购买预算。仅提醒，不代下单。
- **回测验证**：当前代码仅核查近30日历史报告覆盖与候选出现次数，不是收益回测，也不是独立交易数。实际收益回测尚未实现，必须如实标注“未完成”；不可编造胜率或以触及涨停价假定成交。未来收益回测必须使用历史当时的计划与版本、避免未来信息，并计入排队未成交、费用、滑点和 T+1。

三个栏目共用一份报告编号及现有双渠道送达状态，不创建三套重复调度。历史覆盖数增长不单独触发五分钟通知。
